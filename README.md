# edu-agent

面向教师与学生的**智能教学 agent**——把教学能力做成可组合的插件，教师 pack 与学生 pack 按需组装，两端共享同一套底层能力。

## 计划做什么

- **教师侧**：教案生成、出题、组卷、批改辅助、学情报告
- **学生侧**：错题本、错因诊断、针对性变式、随时讲题、知识点总结
- **后续**：教学资源社区（优秀教案与题目的分享生态）

## 不做什么（首期）

- 非数学学科（架构预留，首期不做）
- 直播、互动课堂、作业收发等教学管理功能
- 题库爬虫与版权内容聚合
- 社区（数据格式会为它准备好，但功能晚做）

## 设计文档里最需要讨论的六件事

如果你只读一节，读设计文档的第 2 节（架构主张）；如果你只有五分钟，看这六条：

1. **切原语，不切功能**——"出题""组卷"是功能不是原语，按功能做插件会得到 7 个假装成插件的单体
2. **错题本是地基，不是插件**——它是有状态数据系统，和其余无状态生成任务不是同一个物种
3. **形态无关**——产品形态未定，只有一个层（最外层适配器）知道"用户在哪"
4. **双端差异只能出现在工作流层**——若两端需要各写一套判分，说明原语切错了
5. **可验证性是生命线**——AI 生成的数学内容必须过机器验证才入库，这是与"普通 AI 出题工具"的本质区别
6. **社区的成立前提在第一阶段的 schema**——LeetCode 的社区靠的是机器可评测，不是论坛
