# 写作模块（原始版）

本目录是**从现有内容项目"欧几里德之门"整体拷贝过来的写作工作流**，作为新项目的参考资产。

架构文档 §1.3 把它列为「**教案模块的雏形**」。它已经在一线跑了大半年、产出过 30+ 篇文章，是一套**被验证过**的教学内容生产流程——这比从零设计一套教案生成流程可靠得多。

---

## ⚠️ 先读这一条：这些不是给人读的文档

`skills/` 下的 `SKILL.md` 是**写给 AI agent 的执行指令**，不是项目文档。

- 开头的 frontmatter（`name` / `description` / 触发词）是**机器用的**——AI 靠它判断"什么时候该加载这个技能"
- 正文是**祈使句规范**——"必须""禁止""首先…然后…"，读起来像规章手册，这是正常的
- 里面的"用户"指的是 AI 的使用者（即提出写作要求的人），不是本项目的用户

**所以请不要把它们当成产品需求文档来读。** 把它们当成"一套已经在用的 prompt 工程规范"来看——我们讨论的是**这套流程的哪些部分值得搬进新架构**。

## 八个技能是什么

| 技能 | 一句话 | 类型 |

| `euclids-gate-math-writing` | 写作引擎：精神纲领、写作宗旨、四类文章模板、语言规范、教学法规范六条 | **核心** |

## 映射到新架构

**这一节是本文档的重点。** 哪些能力可以变成新架构的原语，哪些只是这个内容项目的运营规则。

### 可迁移（真正的教学能力）

| 现有组件 | 新架构中的位置 | 迁移价值 |
|---|---|---|
| 精神纲领六条 + 写作宗旨 | pack 层的**风格与价值观约束** | 高——这是"什么样的教学是好教学"的显式表达 |
| 教学法规范六条（变式练习、元认知展示、设问留白、金句节制、名言去重、认知负荷路标） | `gen` 原语的**领域知识** | **很高**——这些是可迁移的教学法原理，与具体学科无关 |
| 两阶段门控（规划 → 批准 → 执行） | L3 工作流的**编排协议** | **很高**——任何"AI 生成教学内容"的场景都需要这个防护 |
| 选题候选制（先给 2~3 个候选，用户选） | L3 交互模式 | 高——避免 AI 单方面决定内容方向 |
| teacher-review / student-review | **persona 服务** | 高——现成的多视角审阅机制，可直接复用于题目与教案 |
| 配图引擎（图型路由 + 质检清单） | `render` 原语的数学部分 | 高——见 `euclids-gate-figure`，含 TikZ/pgfplots/draw.io 三条管线 |
| 命题正确性核查（反例构造、双向检验） | `item.verifiers` 字段的**思想来源** | **很高**——见架构文档 §2.5，这是本产品的核心资产 |

### 项目特有（不要直接搬）

| 现有组件 | 为什么不搬 |
|---|---|
| 公众号编号体系（No 系列 / S 系列） | 内容运营规则，与教学能力无关 |
| 板块轮换、轨道轮换（代数/几何/组合/数论交替） | 同上，是连载策略 |
| 文章长度与节奏规范（5 分钟读完等） | 面向公众号阅读场景，不是教学场景 |
| `article_index.json` 的具体结构 | 是那个项目的存储实现，新架构的 `item` schema 要重新设计 |
| `archive/` 备份与版本号规则 | 内容项目的资产管理约定，非通用需求 |

### 需要重新设计的

| 现有组件 | 问题 |
|---|---|
| `euclids-gate-manage` 的索引机制 | 用 JSON 文件 + 文件系统路径管理文章。新架构的 `store` 原语需要真正的数据层，不能沿用 |
| `euclids-gate-agenda` 的任务追踪 | 目前是 JSON 里的待办列表。若要支撑"学情追踪"，需要换成正式的调度模型（对应架构文档 §5.3 `mastery`） |
| 固定目录结构的假设 | 现有技能假设了"文章在根目录、图在 generated_images/"，新架构不能有这种全局约定 |
